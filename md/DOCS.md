# 使用指南 (Documentation)

---

## ⚙️ 配置

### 在 HA 中添加集成
1. 前往 HA **设置 -> 设备与服务 -> 添加集成**。
2. 搜索并选择 **KittY Controller**。
3. 填写以下字段：

    | 字段 | 说明 |
    |------|------|
    | 设备名称 | 设备显示名（默认：哈基咪），仅用于展示 |
    | API 地址 | 内核外部控制地址，如 `http://192.168.1.1:9090` |
    | 令牌 | 内核 Bearer Token（`external-controller` 的 `secret`） |
    | 使用 HTTPS | 启用后自动将地址统一为 `https://` |
    | 允许不安全的 SSL 证书 | 自签名证书等场景开启 |

4. 点击提交即可完成。
   

### 添加完成后，可在"选项"中调整：

| 选项 | 默认 | 说明 |
|------|------|------|
| 扫描间隔 | 15 秒 | 轮询频率，范围 10 ~ 300 秒 |
| 流媒体可用性检测 | 关 | 开启后探测流媒体解锁状态（需 HA 通过同一代理联网） |
| 额外默认启用的代理组 | 空 | 关键词（逗号分隔），命中组首次注册默认启用 |

## 🧩 实体与服务

**传感器**：上传速度、下载速度、上传流量、下载流量、内存占用、连接数、代理集合数量、规则集合数量、核心更新检查、流媒体解锁状态（Netflix）

**选择器**：代理模式、每个策略组的节点选择器

**按钮**（诊断类，默认禁用）：清除 FakeIP 缓存、清除 DNS 缓存、升级内核、升级 GEO 数据库

**服务**（括号内为服务 ID）：

| 服务 | 说明 | 返回 |
|------|------|------|
| 重启核心（`reboot_core_service`） | 重启远程内核实例 | - |
| 筛选连接（`filter_connection_service`） | 按主机 / 源 IP / 目标 IP 筛选活动连接，可选批量关闭 | 命中数、连接列表 |
| 获取延迟（`get_latency_service`） | 单节点或策略组测速 | 延迟、最快节点 |
| DNS 查询（`dns_query_service`） | 使用内核进行 DNS 解析 | 解析结果 |
| 获取规则（`get_rule_service`） | 按类型 / 内容 / 出口筛选规则 | 规则列表 |
| API 调用（`api_call_service`） | 对内核执行通用 API 请求 | 响应体 |
| 更新订阅（`update_proxy_provider_service`） | 触发代理集合重新拉取订阅 | 集合名称 |
| 更新规则集合（`update_rule_provider_service`） | 触发规则集合重新拉取订阅 | 集合名称 |
| 代理集合健康检查（`healthcheck_provider_service`） | 集合整体测速并回读节点状态 | 存活数、各节点延迟 |
